# Design: Phase 2.1 校准确认（最小闭环）

> 历史设计：本文件记录 Phase 2.1 的决策。现行总裁确认按项目逐人进行，结果须由管理员另行发布；流程以 [Phase 2.2 设计](phase2.2-president-confirm-and-user-activation.md) 和 [UAT 清单](../../UAT测试清单-Phase2.2-总裁确认与激活改密版.md) 为准。

## Problem Statement

Phase 2.0 打分闭环结束后，考核停在 SUBMITTED：分打完了，但没人校准、没人确认、员工看不到结果。Phase 2.1 补完「校准确认」后半段，让 200 人的考核真正「出结果」。

## Demand Evidence

- HR 现用 Excel 手工汇总，单周期 2-3 周；Phase 2 目标是「HR 配置 + 发起」降到 <2 小时。
- 系统已投入 Phase 1 + 2.0，有明确的内部 sponsor 与资源承诺。
- 会话中确认：继峰存在独立的「总裁」终审角色，考核必须走完确认环节才算完成。

## Status Quo

打分完成后，结果靠 Excel 汇总 + 人工核对 + 逐级签字。成本 = 2-3 周 HR 时间；跨项目打分松紧不一致，没有统一校准手段。

## Target User & Narrowest Wedge

- PD（绩效负责人）：跨项目拉平分数。
- 总裁：终审确认。
- 员工：查看本人结果。
- 最小可交付：PD 在汇总矩阵改分拉平 → 总裁确认 → 锁定 → 员工看原始分明细。

## Constraints

- 数据隔离：PD 仅见标记为主 PD 的项目（**新增 inline 过滤逻辑**，不是纯复用 `@PreAuthorize`）；员工仅本人；总裁全员。
- 评估人提交后分数锁定，不可再改；PD 改分走独立审计，不退回重评。
- 结果在总裁确认后才对员工可见。

## Premises

- P1 终审链 = 打分 → PD 拉平校准 → 总裁确认 → 锁定 → 员工查看。
- P2 校准唯一目的 = 跨项目公平（拉平松紧）；🟢🔴 高亮 = 偏离该职能/项目平均分太远（阈值规则见 Open Questions）。
- P3 PD 用「改分」拉平，不退回重评。注：2.0 的 `TaskStateMachine` 已含 RETURN/RETURNED/WITHDRAW；本决策 = 不建 PD 退回 UI，RETURN 路径保持不触发（是否显式移除见下）。
- P4 结果页 = 原始分 + 明细 + 凭证，不做等级/排名（凭证渲染依赖对象存储，见 Open Questions）。

## 数据模型与状态机（2.1 增量）

> 经 /plan-eng-review 锁定（2026-09-17），以下取代本节原始草案：

- **结果落库**：新建 `assessment_result` 表（assessee × period 一行，@Version 乐观锁），存 `original_score` + `adjusted_score`。改分对象是 composite 总分，不落在 `assessment_score`（那是 task × kpi 指标分行）。
- **前置：补建 composite 计算**。`ScoreCalculator.finalScore/projectCompositeScore` 当前零生产调用方——结果生成先聚合每人的 composite 落 `assessment_result`；单组件员工（仅项目/仅职能）权重重归一化 + WARN 标记。
- **审计表**：`score_adjustment` 改键 `assessment_result_id`（不是 task_id/score_id），字段 adjusted_by/old_score/new_score/reason/created_at。
- **状态机在周期级**：周期 `INIT→ONGOING→CALIBRATING→CONFIRMED→COMPLETED`（+ 独立 `abortPeriod` 处理异常关闭；`closePeriod` 仅 CONFIRMED→COMPLETED）。任务态复用现有 `CONFIRMED`，员工可见性由周期态推导。总裁确认用单条 `UPDATE ... WHERE status='CALIBRATING'` 原子翻转。
- **退回死代码移除**：删除 RETURN/RETURNED/WITHDRAW/RESUBMIT 枚举值 + 状态机分支 + 相关迁移列（独立工作项）。
- **迁移修复**：`NEED_PRESIDENT_CONFIRM` 当前 V15 `ON CONFLICT DO NOTHING` 无法覆盖 V3 的 `false`，需 UPDATE 迁移。
- **完整性软门**：进入校准/确认时未 SUBMITTED 的员工跳空不生成结果行，矩阵/确认页显示「N 人未提交」告警。

## Approaches Considered

- A 最小 2.1（采用）：校准（改分 + 离群高亮 + 审计）+ 总裁确认 + 结果查询 + 跨记录比重校验。砍退回 UI、等级映射、校准建议算法；催办降级为「复用 notification 的单个按钮」。
- B 完整 2.1（否）：加回退回重评 + 等级映射 + 建议算法——把刚砍掉的复杂度加回，退回/建议算法大概率死路径，等级线需 HR 先定。
- C 分两段发布（否）：总裁确认被推迟，与「有独立总裁确认」冲突；两段间有临时锁定状态，上线节奏更乱。

## Recommended Approach

A（最小闭环一次做完）。五个决策已把方向收敛清楚，一次做完整比分两段干净；退回重评与等级映射记作 Phase 2.2 候选。

## Open Questions

- 🟢🔴 高亮阈值：默认「项目 × 职能 内偏离平均分 ±1σ」标记离群，待 PD 确认用 σ / IQR / 固定阈值，以及基准是职能平均还是项目平均。
- 改分粒度：默认改「加权总分（composite）」，原始各指标分保留；是否支持按项目批量拉平，待 PD 确认。
- 凭证对象存储：`uploadEvidence` 当前写 `/uploads/evidence/{uuid}` 占位路径、未接对象存储。结果页要渲染凭证，需先把对象存储接入（2.1 前置），或本周期先不渲染凭证。
- 改分后是否通知被改分的评估人？
- 总裁确认页形态：全员矩阵 or 汇总 + 确认按钮（业务未确认时的 fallback = 汇总 + 按钮）。
- 投入比重跨记录校验：在 2.1 范围内（2.0 遗留小项），只校验 PENDING/APPROVED（是否含 REJECTED 待定）。

## Success Criteria

- 200 人周期从「打分完成」到「结果发布」，HR/PD/总裁合计操作 <1 天（区别于 2.0 的「HR 配置 <2 小时」）。
- PD 在一个视图看到跨项目松紧差异并改分（离群高亮可用）。
- 员工在总裁确认后看到本人原始分 + 明细 + 凭证（凭证渲染以对象存储接入为前提）。
- 改分保留原始分 + 审计日志；无 PD 退回 UI。

## The Assignment

开工前，拿一张汇总矩阵线框给继峰的 PD 和总裁看，确认三件事：(1) PD 认可「拉平 = 改分不退回」；(2) 🟢🔴 离群高亮对 PD 有用、他认得出离群点（并顺带敲定阈值和改分粒度）；(3) 总裁确认页他要全员矩阵还是汇总 + 按钮。拿到这三条业务确认，2.1 需求才算真正锁死。

## UI 设计决策（/plan-design-review 锁定 2026-09-17）

> 评审结论：本计划设计完整度 3/10 → 9/10。以下 9 条设计决策已锁，取代本节前的「零 UI 描述」。独立设计评审（Claude subagent，Codex 未装）与本评审收敛一致。

### 三屏信息架构

**1. PD 校准矩阵**（离群优先，不是 200 行平铺）

- 第一眼：顶部分布汇总带（各 项目×职能：人数 / 平均分 / σ / 离群数）+ 橙色「N 人未提交」告警。
- 第二眼：默认按 |偏离度| 降序的表格（离群置顶），顶部「只看离群」开关。
- 第三眼：行内改分 + 原因（见 D11）。
- 表格硬性要求：sticky 表头 + sticky 员工名列 + 横向滚动；列 = 员工 / 项目 / 原始总分 / 调整后总分 / 离群标记 / 操作(改分)。
- 未提交员工：显示为底部暗行 + 「未提交」标签，不计入平均/σ（软提示，不阻断）。

**2. 总裁确认页**（汇总 + 按钮，矩阵作 drill-down）

- 第一眼：就绪一句话「周期 X · N 名员工 · 已校准 · K 处改分 · M 人未提交」。
- 第二眼：关键统计（提交人数 / 未提交 / 改分次数 / 平均分 / 离群数）。
- 第三眼：底部醒目的「确认并发布」danger 按钮。
- 确认动作：二次确认弹窗 + 后果文案「确认后不可撤销，N 名员工将立即看到结果」+ 输入周期名确认（强保护；无发布后纠正路径，仅 abortPeriod）。

**3. 员工结果页**（结果分 = 调整分）

- 第一眼：大字结果分 = `adjusted_score`（无调整时等于原始分）。
- 第二眼：若有调整，并排显示「原始分 → 调整分」+ 差额 + 原因。
- 第三眼：KPI 明细表（指标名 / 权重 / 得分 / 评估人）+ 凭证列（本周期 fallback「凭证暂不可用」，非破图）。

### 锁定决策（D3–D11）

- **D3 结果分 = adjusted_score**，并排显示原始分 + 差额 + 原因（承重墙）。
- **D4 矩阵离群优先**：分布汇总带 + 按偏离度降序 + 只看离群开关。
- **D5 总裁确认页 = 汇总 + 按钮**，矩阵作 drill-down。
- **D6 未提交 = 底部暗行 + 标签**，不计入平均/σ。
- **D7 统一 toast 反馈**：保存/确认 message 成功；409 乐观锁冲突「他人已修改」+ 自动刷新（复用 409 冲突/重复区分）。
- **D8 改分后通知评估人**，带原分→新分 + 原因。
- **D9 总裁确认强保护**：二次确认 + 后果文案 + 输入周期名。
- **D10 离群红/蓝 + ↑↓箭头 + 文字「偏离均值 Nσ」**（色盲安全，不用红/绿）。
- **D11 行内编辑 + 每行显式保存 + 原因预设下拉必填 + 原分 ghost 显示差额**；InputNumber 0–100、两位小数。

### 复用与可访问性

- 三屏一律复用现有 `PageHeader`（面包屑 + `actions[]`）+ `Card borderRadius:8` + 条纹 `Table` + `Tag` 状态色 + `#1890FF` 主色 / `#FF4D4F` 危险色；禁止重新发明一套观感。
- 触控目标 ≥ 44px；离群不依赖单一颜色通道。
