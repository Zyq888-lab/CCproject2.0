# Phase 2 正确性与安全修复（2026-09-28）

本次更新现有 Phase 2 PR，修复已确认的两项结果正确性问题、四项权限/口令问题及附件提交可靠性问题。无需新增数据库迁移。部署后才会在 UAT 生效。

## 确认与分数口径

- 总裁通过确认前，系统检查该项目在当前周期内涉及的所有阶段均已有 PD 校准提交。只提交一个阶段不能通过整项目确认。
- 只有非空确认清单全部通过，且周期内全部项目阶段已提交校准时，才能推进为 `CONFIRMED`。空的一键确认返回 0，不推进周期。
- `original_score` 始终按原始逐项评分计算。未人工调整总分时，`adjusted_score` 按 `calibrated_score` 优先、缺省回退原始分的口径计算，结果明细采用相同口径。
- 有 `score_adjustment` 审计记录的人工总分调整优先，重新生成结果不会覆盖它。不能仅凭原始分与调整分不同判断是否人工调整，否则逐项校准后的后续变更会被冻结。
- 既有已发布结果不会自动批量回算。本次修复作用于后续正常的结果生成；历史结果如需重新核算，应单独核对后处理。

## 权限边界

| 操作 | 允许对象 |
| --- | --- |
| 调整项目任务的逐项 KPI | ADMIN，或具有全局 PD 角色且为该任务实际项目、阶段主 PD 的员工 |
| 人工调整跨项目汇总总分（旧接口） | ADMIN |
| 分配、移除角色，标记或取消主角色 | ADMIN，或实际项目、阶段的主 PM；URL 项目/阶段须与分配记录一致 |
| 确认、归档项目阶段 | ADMIN，或该项目、阶段的主 PM |
| 跨阶段同步主总裁 | ADMIN，或同时负责源阶段和全部目标阶段的主 PM；先校验全部权限再修改 |
| 下载评分凭证 | ADMIN、任务考核人、已提交项目任务所属阶段的主 PD/主总裁，或结果已对本人可见的被考核人 |

仅有全局 PD/PM 角色不再足以修改其他项目或阶段。未登记到评分记录的文件不提供下载，知道文件 URL 不代表有访问权限。职能任务的附件不通过项目角色授权。

## 附件保存

上传、草稿保存和评分提交要求任务处于 `IN_PROGRESS`，并持有同一任务行锁，避免评分提交与附件替换并发。提交/草稿接口保留服务端上传登记的 URL，忽略客户端自传的凭证 URL；评分提交后拒绝新上传。

新增文件写入成功但数据库更新冲突时，接口返回 409，并清理本次新文件。上传失败不会返回成功 URL。下载拒绝非法文件名、路径穿越和文件符号链接；非图片/PDF 按下载附件返回，并设置 `nosniff`。

存储仍是本地磁盘。旧文件被替换后的回收、多实例共享、备份和对象存储迁移仍需另行规划；本次没有自动搬迁或删除历史附件。

## UAT 升级配置

执行 `deploy/uat/deploy-full.ps1`、`deploy-uat.ps1` 或 `deploy-uat-update.ps1` 前，在执行终端或部署秘密管理工具中提供以下环境变量，脚本不再内置口令：

| 环境变量 | 用途 |
| --- | --- |
| `DATASOURCE_PASSWORD` | 当前 UAT PostgreSQL 连接口令；必须与数据库实际配置一致 |
| `ADMIN_BOOTSTRAP_PASSWORD` | 新建管理员或轮换旧默认口令所用的强引导口令，12–128 字符，包含大小写字母、数字和特殊字符 |
| `APP_UPLOAD_DIR` | 持久附件目录的绝对路径；应指向已有附件的位置 |
| `POSTGRES_SUPERPASSWORD` | 仅全新安装 PostgreSQL 时由 `installers/install-all.ps1` 使用 |
| `E2E_ADMIN_PASSWORD` | 仅运行真实管理员登录 E2E 时使用；须为已完成首次改密后的当前口令 |

1. 核对旧服务实际的附件落盘目录。若原先使用相对目录，先确认旧进程启动位置，不能直接改为新的空目录。需要迁移时，先备份并复制旧文件，再将 `APP_UPLOAD_DIR` 指向新位置。
2. 数据库口令曾进入 Git 历史。删除当前脚本中的口令不等于轮换数据库口令；应由环境管理员在数据库侧轮换，并同步部署变量。此次代码工作不操作 UAT 数据库、不重启服务、不改写 Git 历史。
3. 检查管理员引导口令符合上述强度要求。若发现管理员仍用旧默认口令，启动时会轮换为引导口令并强制首次改密；未配置强口令时拒绝启动。已有非默认口令保留。首次初始化同时创建账号和角色，失败会回滚。
4. 配置完成后按既有部署流程更新。后端固定以 UAT 部署目录为工作目录启动，附件目录由环境变量决定。不要把口令写进脚本、命令记录或提交记录。
5. 部署后分别用考核人、负责 PD/PM、其他项目 PD/PM 与普通员工验证权限；检查旧附件、新附件、校准后的总分、逐项明细及总裁确认门槛。
