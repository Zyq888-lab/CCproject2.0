# v2.14.1.0：周期监控项目角色

本版本在考核周期的监控列表中，在“项目”之后增加“项目角色”。每一行仍对应原有考核任务；同一个人在相同项目、阶段的多个角色分别显示为标签。CSV 导出使用相同数据，在同一个单元格内换行，员工筛选继续生效。

角色按被考核员工、项目编码、项目阶段匹配，排除已删除的角色分配。职能考核、未分配角色的任务显示“—”。角色取自当前有效分配，不是考核发起时的历史快照；后续调整角色配置会影响监控显示。

本版本同时归档此前已批准、已在生产使用的公司 Logo 与系统名称调整。没有新增路由、数据库迁移、评分写入或审批规则。

## 验证

- 后端全套 `mvn -q test`：360 项通过，包括 13 项监控测试。
- 浏览器回归：3 项通过，覆盖独立标签、任务行数不变、CSV 单元格换行和筛选导出；模拟业务写请求为 0。
- `npm run build` 与后端 JAR 打包通过。
- 监控页面 ESLint 与基线比较没有新增错误；仍有一项原有 `react-hooks/set-state-in-effect` 问题。前端构建仍提示主包体积较大。
- 自动化页面回归使用模拟 API，不等同于生产数据上的完整业务验收。

## 发布与回滚

按用户要求仅更新生产，跳过 UAT。发布前校验生产 JAR 与新包的依赖相同，备份原 JAR、前端资源、启动脚本与配置，保留原配置、上传目录和数据库。

发布前先使用独立的本机回环端口和只读数据库连接检查候选后端能正常启动；正式替换时暂时停用保活任务，更新 JAR 后重新启动原任务，验证后再切换前端入口。Nginx 配置保持原样。

回滚使用本次服务器备份恢复原 JAR 和前端入口，再启动原保活任务。没有数据库迁移，不需要回退数据库。具体提交、包哈希、备份位置和上线验证结果保存在发布清单与部署报告中。
