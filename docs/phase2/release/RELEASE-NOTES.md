# Phase2 发布说明（2.14.0.0 准备版）

本文统一说明整个 Phase2 的最终功能，不把子阶段当作四个独立上线版本。版本状态与交付物见 [发布总览](README.md)，历史变更原文保留在 [CHANGELOG](../../../CHANGELOG.md)。

## 用户可使用的功能

| 身份 | 功能 |
| --- | --- |
| 员工 | 按周期申报多个项目及阶段的投入比重；查看本人指标和发布后的结果 |
| PM | 在待审批中处理自己负责项目、阶段的参与申请；在权限范围内管理角色和阶段 |
| 评估人 | 接收考核任务，填写项目或职能 KPI 分数、保存草稿、上传评分凭证并提交 |
| PD | 查看负责项目、阶段的校准矩阵，按项目及阶段筛选，逐项校准 KPI 并提交校准；处理总裁退回的人员 |
| 总裁 | 查看负责项目的确认清单，逐人查看评分、通过或退回；查看评分仅显示所选人员在该项目的明细 |
| 管理员 | 配置规则、激活账号、发起考核、查看监控和差异、管理结果发布与周期归档 |

角色的全局菜单权限与实际项目、阶段归属共同决定操作范围。拥有 PM 或 PD 角色，不代表可以处理所有项目。

## 完整操作顺序

1. 管理员配置员工、岗位权重、KPI、项目阶段、主角色和考核周期，激活所需账号。新账号首次登录先修改密码。
2. 员工选择周期，提交项目、阶段和投入比重；对应项目、阶段的主 PM 审批。
3. 管理员发起考核；评估人完成项目和适用的职能指标评分、上传凭证并提交。
4. 进入校准后，PD 在自己的项目、阶段范围内查看与调整逐项 KPI，填写原因并提交校准。
5. 负责总裁按项目逐人查看评分、确认或退回。总裁确认需等待该项目相关阶段的 PD 提交完成。
6. 退回的人员由 PD 重新校准、提交后，再由总裁确认；其他人员按各自状态处理。
7. 确认清单满足条件后，周期进入待发布；管理员另行发布，员工才能查看最终结果。
8. 发布后可由管理员正常关闭周期归档。

具体验收数据与每一步预期见 [验收清单](ACCEPTANCE.md)。本次整理没有执行上述流程。

## 周期状态与结果可见性

| 状态 | 含义 | 员工最终结果 |
| --- | --- | --- |
| `INIT` | 未开始，可录入参与 | 不公开 |
| `ONGOING` | 进行中、评分阶段 | 不公开 |
| `CALIBRATING` | 校准与总裁确认阶段 | 不公开 |
| `CONFIRMED` | 确认完成，等待管理员发布 | 不公开 |
| `PUBLISHED` | 已发布 | 可见 |
| `COMPLETED` | 正常关闭后归档 | 可见 |

以上描述正常闭环。**强制关闭不是正常发布的替代操作**，其可见性限制仍见 [已知问题](KNOWN-ISSUES.md)。未完成评分人员是否被遗漏也需要验收核对，不能只看到周期状态就认为全员完成。

## 分数与附件

- 原始 KPI 分数继续保留；PD 的逐项校准分作为覆盖分参与调整后小计、总分和明细。
- 项目小计与员工整个周期的总分是不同层级；多项目按项目、阶段展示，结果页显示对应项目和阶段。
- 有审计记录的人工总分调整优先；已有已发布结果不会因升级自动批量回算。
- 新上传凭证真实保存到服务器附件目录，受任务归属权限约束；评分提交后不能替换附件。
- 项目评分凭证在符合条件的 PD 校准、管理员监控及个人结果中提供入口；职能凭证不通过任意项目角色授权，不能把“项目主 PD”理解为全部职能附件的权限。
- 附件仍使用本地磁盘；旧附件是否可打开取决于原文件是否存在以及目录是否正确，升级不自动搬迁文件。

## 账号和部署变化

管理员初始化或旧默认口令轮换需要显式提供强引导口令；已有非默认管理员口令不会被覆盖。UAT 脚本改为从环境变量取数据库口令和附件目录，删除脚本中的旧口令不等于轮换数据库实际口令。

发布时应交付同一提交构建的前端、后端和迁移；部署步骤见 [部署与回滚手册](DEPLOYMENT.md)。当前已知缺陷与未验证范围见 [已知问题](KNOWN-ISSUES.md)。
