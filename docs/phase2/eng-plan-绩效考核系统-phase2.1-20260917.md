## 〇、我该怎么用这个规划

阶段2.1 做两件事，串成一条线：

1. **角色主标记**：修「同角色两个人同时收到打分任务」的路由错位——同角色出现 2 人时标一个「主」，只有主审批/打分。
2. **校准确认**：把考核从「分打完了停在 SUBMITTED」推进到「出结果」——PD 拉平校准 → 总裁确认 → 锁定 → 员工看结果。

两者共用一个概念：**「主」标记**。角色主标记里 PD 标主看项目，校准确认里 PD 校准矩阵的可见范围也是「标记为主 PD 的项目」——同一句，两处必须一致。

## 二、API接口说明（带场景化描述）

> 标「已有」= 阶段2.0 已上线；标「新建」= 阶段2.1 先不实施，仅规划。

### 2.1 任务生成 — task

**场景：HR 创建考核周期并点「发起」后，系统按角色分配给每位考核人生成打分任务；同角色若有多人，只有「主」收到。**

| 方法 | 路径 | 状态 | 场景化描述 |
|------|------|------|-----------|
| POST | `/api/v1/tasks/{periodId}/launch` | 已有（改） | HR 发起周期，TaskGeneratorService 全周期生成任务。**改动**：同角色多人时只给 `is_primary=true` 的人发，无主则跳过该角色 + 记 NO_PRIMARY_ASSESSOR 差异 + 通知 admin |
| PUT | `/api/v1/tasks/{id}/start` | 已有 | 考核人点「开始打分」，任务态进入打分中 |
| PUT | `/api/v1/tasks/{id}/cancel` | 已有 | 取消任务 |

### 2.2 参与录入审批 — participation

**场景：员工申报项目参与，系统判定「被分配到该项目即可」审批；阶段2.1 不改这里的审批路由（谁批、是否走主PM 推迟）。**

| 方法 | 路径 | 状态 | 场景化描述 |
|------|------|------|-----------|
| GET | `/api/v1/participations` | 已有 | 员工/PM 查看参与记录 |
| POST | `/api/v1/participations` | 已有 | 员工提交参与申报 |
| PUT | `/api/v1/participations/{id}/approve` | 已有（不改） | 审批通过；非 ADMIN 判定为「被分配到该项目即可」 |
| POST | `/api/v1/participations/{id}/resubmit` | 已有 | 驳回后重新提交 |

### 2.3 项目角色分配 — roleassignment（阶段2.1 核心改动）

**场景：HR 给某项目的某角色分配 2 个人（如 PDL 有张三、李四），勾选其中一个为「主」，只有主收到打分任务。**

| 方法 | 路径 | 状态 | 场景化描述 |
|------|------|------|-----------|
| GET | `/api/v1/projects/{projectCode}/{projectStage}/assignments` | 已有 | 查看项目下所有角色分配 |
| GET | `/api/v1/projects/assignments/summary` | 已有（改） | 跨项目汇总。**改动**：`@RequestParam isPrimaryPd` → `isPrimary`，后端手写 SQL 同步改列名 |
| POST | `/api/v1/projects/{projectCode}/{projectStage}/assignments` | 已有 | 分配员工到角色 |
| PUT | `/api/v1/projects/{projectCode}/{projectStage}/assignments/{assignmentId}/toggle-primary-pd` | 已有（改语义） | 勾选「主」。**改动**：从「项目级 PD 负责人」改为「该角色该阶段唯一主」，任意角色可标，unmark 范围按 projectCode+stage+roleCode |
| DELETE | `/api/v1/projects/{projectCode}/{projectStage}/assignments/{assignmentId}` | 已有 | 移除分配 |

### 2.4 PD 校准 — calibration（新建）

**场景：打分完成后 PD 打开校准矩阵，看跨项目松紧差异，对离群分改分拉平；改分保留原始分 + 审计。**

| 方法 | 路径 | 状态 | 场景化描述 |
|------|------|------|-----------|
| GET | `/api/v1/periods/{periodId}/calibration` | 新建 | 加载校准矩阵：员工×项目×原始总分×调整分 + 离群标记 + 未提交告警 |
| PUT | `/api/v1/periods/{periodId}/calibration/adjust` | 新建 | PD 改某员工 composite 分，写 assessment_result.adjusted_score + score_adjustment 审计 |

### 2.5 总裁确认 + 员工结果 — result（新建）

**场景：PD 校准完后总裁点「确认并发布」，员工才看到本人结果；结果分 = 调整分。**

| 方法 | 路径 | 状态 | 场景化描述 |
|------|------|------|-----------|
| POST | `/api/v1/periods/{periodId}/confirm` | 新建 | 总裁二次确认（输入周期名强保护），单条 UPDATE 原子翻转 CALIBRATING→CONFIRMED |
| GET | `/api/v1/periods/{periodId}/result` | 新建 | 员工看本人结果：调整分 + 原始分明细 + KPI + 凭证 fallback |

### 2.6 差异报告 — dashboard

**场景：ADMIN 在仪表盘看到「N 条异常」，其中新增「角色 X 有 N 人未标主」类型。**

| 方法 | 路径 | 状态 | 场景化描述 |
|------|------|------|-----------|

| GET | `/api/v1/dashboard/pending-count` | 已有 | 待处理差异数（红点） |

### 7.1 角色主标记

`resolvePrimaryAssessors` 四象限（`TaskGeneratorServiceTest`）：

| 场景 | 期望 |
|------|------|
| 1 人（无主） | 照常发（单人不需标主，不触发 NO_PRIMARY_ASSESSOR） |

- 结果落库：改分保留 original_score + adjusted_score + 审计行
- 状态机：CALIBRATING→CONFIRMED 并发只成功一次；员工可见性由周期态推导
- 完整性门：未提交员工不计入平均/σ，矩阵显示暗行 + 告警
- 409 乐观锁：改分/确认冲突时 toast「他人已修改」+ 刷新
- composite：单组件员工权重重归一化，无 NaN/除零

### 7.3 关键路径

**路径1（打分→出结果）**：发起周期 → 同角色 2 人标主只发主 → 打分 SUBMITTED → PD 校准改分 → 总裁确认 → 员工看调整分
**路径2（未标主兜底）**：发起周期 → 同角色 2 人无主 → 差异报告出现 NO_PRIMARY_ASSESSOR + admin 收通知，不误发两人

## 十三、UI设计规范（Design Review 输出）

> 以下 9 条设计决策（D3-D11）来自校准确认的 /plan-design-review（评分 3/10→9/10）；角色主标记的 UI 改动（标记主按钮）见 T6。

### 13.1 三屏信息架构

**1. PD 校准矩阵**（离群优先，不是 200 行平铺）
- 顶部分布汇总带（项目×职能：人数/平均分/σ/离群数）+ 橙色「N 人未提交」告警
- 默认按 |偏离度| 降序，离群置顶 + 「只看离群」开关
- 行内改分 + 原因；sticky 表头 + sticky 员工名列 + 横向滚动
- 未提交员工显示底部暗行 + 标签，不计入平均/σ

**2. 总裁确认页**（汇总 + 按钮，矩阵 drill-down）
- 就绪一句话「周期 X · N 名员工 · 已校准 · K 处改分 · M 人未提交」+ 关键统计
- 底部「确认并发布」danger 按钮 + 二次确认 + 后果文案 + 输入周期名（强保护，无发布后纠正，仅 abortPeriod）

**3. 员工结果页**（结果分 = 调整分）
- 大字结果分 = adjusted_score；有调整并排「原始分 → 调整分」+ 差额 + 原因
- KPI 明细表 + 凭证列（fallback「凭证暂不可用」，非破图）

### 13.2 锁定决策（D3-D11）

- **D3** 结果分 = adjusted_score，并排原始分 + 差额 + 原因（承重墙）
- **D4** 矩阵离群优先：分布汇总带 + 按偏离度降序 + 只看离群开关
- **D5** 总裁确认页 = 汇总 + 按钮，矩阵 drill-down
- **D6** 未提交 = 底部暗行 + 标签，不计入统计
- **D7** 统一 toast：保存/确认成功；409 乐观锁冲突「他人已修改」+ 刷新（复用 409 冲突/重复区分）
- **D8** 改分后通知评估人，带原分→新分 + 原因
- **D9** 总裁确认强保护：二次确认 + 后果文案 + 输入周期名
- **D10** 离群红/蓝 + ↑↓箭头 + 文字「偏离均值 Nσ」（色盲安全，不用红/绿）
- **D11** 行内编辑 + 每行显式保存 + 原因预设下拉必填 + 原分 ghost 显示差额；InputNumber 0-100 两位小数

### 13.3 复用与可访问性

- 三屏复用 `PageHeader` + `Card borderRadius:8` + 条纹 `Table` + `Tag` 状态色 + `#1890FF`/`#FF4D4F`/`#8C8C8C`，禁止重造观感
- 触控目标 ≥44px；离群不依赖单一颜色通道
- 角色分配「标记主」按钮：文案「该角色主」，任意角色可标，与「主PD」旧语义脱钩
